## 坑 1 · adb 执行无任何输出，退出码 127

**现象**

```bash
$ adb.exe version
$ echo $?
127
```

没有报错、没有提示、什么都没有。

**真因**

用了 adbutils / python-adb 自带的 `adb.exe` 单文件。官方 adb 在 Windows 上依赖两个 DLL：

```
adb.exe
AdbWinApi.dll
AdbWinUsbApi.dll
```

少一个就启动失败，而且**不弹 DLL 缺失提示**，直接静默失败。

**解法**

装官方 platform-tools。这也是本项目不用 adbutils 的原因 ——
与其埋一个排查黑洞，不如让用户一次性装个完整的。

顺带一提：某些 Python 项目查找 adb 时只会去 PATH 里找，不会自动发现
依赖包里捆绑的那份。如果你的工具报"找不到 adb"，八成也是这个逻辑。

## 坑 2 · 包名全部报 `Unknown package`

**现象**

明明 `pm list packages` 里能看到这些包，但逐个 disable 时全报：

```
Failure [INSTALL_FAILED_...]  或  Unknown package: com.miui.analytics
```

**真因**

Windows 行尾。清单文件写成了 **CRLF**，每行末尾藏着一个 `\r`，
于是传给 pm 的包名实际是 `com.miui.analytics\r` —— 当然找不到。

Python 在 Windows 下 `open(path, 'w')` 默认就把 `\n` 翻译成 `\r\n`，非常容易中招。

**解法**

落盘时显式指定 LF：

```python
open(path, "w", encoding="utf-8", newline="\n")
```

本项目把所有会交给 adb 的文件写入都收敛到了 `debloat.write_text()`，统一强制 LF。
另外 `adb.py` 的 `normalize_text()` 会再做一次 `\r` 剥离，双重保险。

**自查**

```bash
grep -l $'\r' freeze_list.txt && echo "含 CR，必须修"
```

## 坑 3 · bash 循环里 adb 只处理了第一行就结束

**现象**

```bash
while read -r p; do adb shell pm disable-user "$p"; done < freeze_list.txt
```

只处理了第一行，然后循环就退出了。

**真因**

`adb` 会把重定向给 `while` 循环的那个文件当成自己的**标准输入**吃掉。
它把自己当成一个"从 stdin 读数据再输出"的程序，一口气把文件内容吸走，
等回到循环时文件指针已经 EOF。

**解法**

切断 adb 的 stdin：

```bash
while read -r p; do adb shell pm disable-user "$p" < /dev/null; done < freeze_list.txt
```

Python 侧等价处理：`subprocess.run(..., stdin=subprocess.DEVNULL)`，
本项目 `adb.py` 里已经这么写了。

## 坑 4 · 「USB 调试」开了，但 adb 点不动手机

**现象**

能连上、能读信息，但任何涉及点击或修改设置的动作都被系统拒绝。

**真因**

漏开了「**USB 调试（安全设置）**」。它和「USB 调试」是两个独立开关。

**额外难点**

即便确认打开（显示绿色），有些机器**当时也不生效**。
本项目实测在 HyperOS 上多次遇到，最后是靠**重启手机**解决的。

具体顺序：

1. 开发者选项里确认「USB 调试」+「USB 调试（安全设置）」都开着；
2. 打开时如果弹了风险提示，**必须等倒计时结束**再点确定，否则开关会弹回关闭；
3. 仍然被拒 → **重启手机**；
4. 重启后确认两个开关没掉，重新插数据线，手机上重新授权（勾「始终允许」）；
5. 全程保持手机**解锁亮屏**。

前提条件：插了 SIM 卡 + 登录了厂商账号，否则这个开关可能压根不让你开。

## 坑 5 · 「不得不读的失败」：ROM 拒绝禁用

**现象**

```
Exception occurred while executing 'disable-user':
java.lang.SecurityException: Cannot disable system packages
```

55 个候选，48 个是这个。

**这不是坑，这是设备的真实回答。** 但这个答案来得实在太晚了 ——
在此之前会浪费掉几十次尝试，还容易误判成命令错误。

详见 [02-为什么先探测.md](02-为什么先探测.md)，这也是本项目 `probe` 命令存在的理由。

## 坑 6 · UAD 清单拉不下来

**现象**

```bash
curl https://raw.githubusercontent.com/.../uad_lists.json
curl: (56) Recv failure
```

或者 git clone 报 TLS schannel 错误中断。

**解法**

本项目在 `uad.py` 里做了四级 fallback：

```
urllib 直连 raw → curl raw → codeload 整仓打包 → git 浅克隆 → 本地缓存
```

任何一条通就行，结果统一落到 `.cache/uad_lists.json`，之后断网也能用。
实在都拉不到，就手动下载丢进 `.cache/uad_lists.json`。
