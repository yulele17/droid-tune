# 03 · 流畅调优

不 root 的前提下，「让手机感觉更快」最有效的其实不是超频，
而是**把拖泥带水的动作缩短、把不该占的资源还回来**。

对应三件事：

## 1. 动画缩放（收益最高，零成本）

安卓打开/切换 App 有动画，默认时长给的是保守值。把它压到一半，主观跟手感提升非常明显。

```bash
python -m tune smooth --scale 0.5
```

改动的是这三个 `global` 设置：

| key | 含义 |
|---|---|
| `window_animation_scale` | 窗口打开的动画 |
| `transition_animation_scale` | 界面切换的动画 |
| `animator_duration_scale` | 控件自身的动画 |

取值说明：

| 值 | 效果 | 适合 |
|---|---|---|
| `1.0` | 系统默认 | 原厂体验 |
| `0.5` | **推荐**，明显变快又不突兀 | 绝大多数人 |
| `0` | 完全关闭动画，瞬间切换 | 追求极致响应，但部分过渡会显得生硬 |

原值会被存进快照，随时 `restore` 回来。

## 2. 后台进程限制（省电，略有取舍）

```bash
python -m tune smooth --bg-limit 3
```

限制系统最多同时保留几个后台进程。后台常驻少了，内存压力和耗电都会下降。

⚠️ **不要设 1。** 那样微信、邮件、日历提醒都会开始延迟，属于典型的因小失大。
建议区间 **3~4**。

如果之后发现某个 App 收消息变慢了，把它加进电池优化的「不受限制」白名单，
或者直接还原：

```bash
python -m tune restore <快照文件>
```

## 3. 内存扩展（要不要关，看情况）

这个功能借用存储空间当虚拟内存。听起来是好事，但在中低端存储上，
swap 的随机读写反而可能造成卡顿感。

```bash
python -m tune memory
```

⚠️ **本工具只探测，不自动改。** 原因很实在：实测在 HyperOS 上读到的值
形如 `miui_memory_size=256 GB`——这明显不是标准数字格式的 GB 值，
照着它去写有把内存管理搞乱的风险。不确定性摆在这儿，决定权交给人。

手动关闭路径：

```
设置 → 省电与电池 → 内存扩展 → 关
```

（各 ROM 入口名不同，直接在设置页顶部搜「内存扩展」最快）

什么时候**不该**关：如果你明显感觉到多开 App 时频繁重新加载，说明这块虚拟内存你真用得上，那就留着。

## 不做的事（网上流传很广，但这里不推荐）

| 项目 | 实际情况 |
|---|---|
| 关闭「MIUI 优化」 | 容易让状态栏、通知、权限弹窗出现异常，得不偿失 |
| 强制 GPU 渲染 | 新机型几乎没有收益，还可能更耗电、偶发闪退 |
| 停用 HW 叠加层 | 同上，少数机型直接黑屏 |
| 禁用系统更新 | 能防后台偷更，但会漏安全补丁 |

## 关于天花板

真正的性能底层调优——CPU 调度策略、温控阈值、IO 调度器、IO 预读——
**必须 root 或换内核**，不 root 到这里就到顶了，这是事实。

但话说回来：近几年的中端 SoC 本身性能并不弱，
日常感受到的"卡"，多半来自动画拖沓、后台臃肿、广告SDK、预装自启这些**可以清理的东西**。
把它们清掉，体感提升通常比折腾内核来得实在，而且不用承担变砖的风险。
