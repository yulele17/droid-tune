# 05 · 还原

所有改动都可逆。按场景选方式。

## 用快照一键还原（推荐）

每次执行 `smooth` / `freeze` 都会生成一份 JSON 快照，里面记录着**改动之前的值**
和这次实际冻结成功的包名。

```bash
python -m tune snapshot
# snapshot-RedmiNote13Pro-20261031-192233.json
#     设备 Redmi Note 13 Pro / 1a43****   时间 2026-10-31 19:22:33
#     settings 项 4  已冻结包 7

python -m tune restore snapshot-RedmiNote13Pro-20261031-192233.json
```

快照纯文本，不联网、不依赖原始清单，离线也能还原。
跨设备还原会被序列号检查拦住（防止还原错机器），确实要跨机就加 `--force`。

## 只还原动画和后台限制

还原成系统默认：

```bash
adb shell settings put global window_animation_scale 1.0
adb shell settings put global transition_animation_scale 1.0
adb shell settings put global animator_duration_scale 1.0
adb shell settings delete global background_process_limit
```

（`delete` 比塞一个值更干净，等于回到"从未设置过"的状态）

## 只解冻某几个包

```bash
# 单个
python -m tune unfreeze --package com.miui.cleanmaster

# 一批
python -m tune unfreeze --file snapshots/freeze_list.txt
```

等价的裸 adb 写法：

```bash
adb shell pm enable --user 0 com.miui.cleanmaster
```

## 冻结太多、不确定该还原哪些

把当前所有已禁用（冻结）的包列出来看看：

```bash
adb shell pm list packages -d
```

它会输出所有处于 disabled 状态的包（包括本次之前就有的），
对照 `plan` 导出的 Markdown 清单挑要恢复的即可。

## 极端情况：冻结后出现异常

按严重程度递增：

1. **某个 App 不能用了** → 单独 `pm enable` 恢复它；
2. **设置界面反复弹窗** → 恢复最近一批冻结的包（用快照）；
3. **进不了桌面 / 反复崩溃** → 先别慌，adb 大概率还能连（adb 不依赖被冻的应用）：
   ```bash
   adb shell settings list global        # 先确认 adb 通
   python -m tune restore <最近的快照>
   ```
4. **连 adb 都不通了** → 重启手机进 Recovery → 清除缓存（不是清数据），
   多数系统组件会在重启时重新初始化。
5. **真开不了机** → 厂商售后。这也是为什么 AGENTS.md 严禁 `pm uninstall`：
   `disable-user` 在最坏情况下仍有挽回空间，卸载没有。

> 一句话：**冻**是软删除，留了后路；**卸载**才是真删除。本项目只做前者。

## OTA 之后

系统大版本升级会把冻结状态重置（被冻结的 App 重新出现）。
这不是项目出 bug，重跑一次 `plan` + `freeze` 就好。
