# 04 · 预装冻结

## 前提：先 probe

**做这一步之前请务必先跑完 `probe`。** 如果你的 ROM 属于「基本不可行」那一档，
这一整章对你意义不大，请转 [02-为什么先探测.md](02-为什么先探测.md)。

## 名单从哪来

本项目的包名清单来自 [UAD-ng](https://github.com/Universal-Debloater-Alliance/universal-android-debloater-next-generation)
官方维护的 `uad_lists.json`（5000+ 条，社区长期维护），而不是自己列几个包名糊弄。

流程是**交叉比对**：

```
UAD 官方清单  ×  你这台机真实安装的包列表  →  候选名单  →  本地保护名单过滤  →  最终清单
```

好处是：清单里的每个包都确定装在你机器上，不会出现"冻了个不存在的东西"的尴尬。

`plan` 命令会按这两种方式之一取清单：

1. 联网直取（四种通道自动 fallback：raw → curl → codeload 打包 → git 浅克隆）
2. 命中本地缓存 `.cache/uad_lists.json`

断网也不怕，只要之前拉过一次。

## UAD 的四级分级怎么看

| UAD 分级 | 含义 | 本项目默认态度 |
|---|---|---|
| `Recommended` | 社区公认可冻，多为遥测/广告/无代码 overlay | **纳入默认清单** |
| `Advanced` | 需要一定判断力，混着有实际功能的 App | 默认排除，加 `--include-advanced` 才纳入 |
| `Expert` | 需要了解后果 | 排除 |
| `Unsafe` | 已知危险 | 排除 |

为什么 `Advanced` 默认排除：里面确实掺了「音效」「相册编辑器」「悬浮球」这类
**用户可能真的在用**的东西。宁可少冻十个，不能冻错一个。

## 本地保护名单（第二道闸）

光看 UAD 分级不够，它毕竟是跨机型的社区共识，落到具体 ROM 上会偏。
项目里额外维护了 `data/keep-critical.txt`，命中即**坚决不动**。

它的收录标准是「冻了会掉功能」，典型条目及理由：

| 包 | 冻了的后果 |
|---|---|
| `com.miui.packageinstaller` | 国行机型会开机卡死（bootloop） |
| `com.miui.gallery` | 发不了图片，连截图都看不了 |
| `com.xiaomi.bluetooth` | 蓝牙可能直接不可用 |
| `com.xiaomi.simactivate.service` | SIM 卡可能识别不出来 |
| `com.xiaomi.trustservice` | 支付/登录场景异常 |
| `com.miui.face` | 人脸解锁失效 |
| `com.miui.securitycenter` | 权限管理入口没了 |

名单也刻意**不放宽泛通配**（比如不写 `com.coloros.*`），
否则会把厂商名下几乎所有包一并保护起来，这一章就没意义了。欢迎提 PR 补条目。

## 生成清单

```bash
python -m tune plan --export 我的清单.md
```

产物两份：

- `我的清单.md` —— 带 UAD 说明的人读版本，适合逐条勾；
- `snapshots/freeze_list.txt` —— 纯包名，**强制 LF 行尾**（见 [06-踩坑实录](06-踩坑实录.md) 第 2 条）。

## ⚠️ 必须人工过目一遍

这一点别偷懒。默认清单里仍然可能出现这样的东西：

```
com.miui.calculator     计算器
com.miui.notes          便签
com.miui.weather2       天气
com.miui.screenrecorder 录屏
```

从 UAD 的角度看它们"可冻"，因为它们是可被替代的应用；
但从你的角度看，**你可能每天都在用**。工具无权替你决定这个。

打开导出的 Markdown，把想留的行划掉即可。

## 执行

```bash
python -m tune freeze --dry-run    # 先看清楚要动哪些
python -m tune freeze
```

## 怎么看结果

`freeze` 会把结果分四类如实报告：

| 类别 | 含义 | 是不是故障 |
|---|---|---|
| 冻结成功 | 已禁用 | — |
| **系统锁死** | ROM 拒绝：`Cannot disable system packages` | **不是**。这是设备的真实限制 |
| 未安装 | 这台机器上没这个包 | 不是 |
| 未知返回 | 其它 | 要看 raw 输出 |

**锁死 ≠ 失败。** 请对照 probe 的结论理解它：
如果 probe 早就说了这台机器允许比例只有 17%，那这里锁死 80% 是符合预期的，工具工作正常。

锁死比例超过一半时，工具会主动建议你改走 UI 路线。

## 关于恢复

所有成功冻结的包名都写进了 `snapshots/snapshot-*.json`，见 [05-还原.md](05-还原.md)。

另外注意：**系统 OTA 升级后，冻结状态可能被重置**，届时回头重跑一次即可，不算异常。
